## Directory Purposes

**`src/`:**
- Purpose: Node.js backend business logic and HTTP API
- Contains: Express routes, x402 protocol, auth, persistence, chain integration
- Key files: `server.ts` (entry), `app.ts` (Express factory), `config.ts` (env parsing)

**`src/routes/`:**
- Purpose: HTTP endpoint handlers grouped by concern
- Contains: auth flow, seller API, payment gateway, facilitator interface
- Key files: `gateway.ts` (main payment path), `api.ts` (endpoint CRUD)

**`src/x402/`:**
- Purpose: x402 protocol implementation (signature, verification, settlement)
- Contains: EIP-712 signing, payment requirements, facilitator logic, on-chain integration
- Key files: `protocol.ts` (PaymentRequirements), `facilitator.ts` (verify/settle orchestration), `chain.ts` (EIP-3009 on-chain)

**`src/erc8004/`:**
- Purpose: Optional trustless agent identity and reputation system
- Contains: Registry lookups, policy enforcement
- Key files: `registry.ts` (resolve agent, enforce minReputation)

**`web/`:**
- Purpose: React dashboard for sellers to manage gates and view earnings
- Contains: Pages, components, auth context, wallet integration
- Key files: `pages/Dashboard.tsx` (main seller UI), `lib/auth.tsx` (SIWE), `lib/wallet.tsx` (MetaMask)

**`api/`:**
- Purpose: Vercel serverless adapter
- Contains: Single request handler that bridges Vercel's Node runtime to Express
- Key files: `index.ts` (fixes request body streaming)

**`contracts/`:**
- Purpose: Solidity smart contracts for USDC and agent identity
- Contains: Test USDC ERC-20, ERC-8004 identity registry, reputation tracking
- Key files: `MockUSDC.sol`, `ERC8004.sol`

**`scripts/`:**
- Purpose: One-time deployment and setup tasks
- Contains: Testnet configuration, contract deployment
- Key files: `deploy.ts` (USDC), `setup-fuji.ts` (Avalanche Fuji RPC + env)

- `src/server.ts`: Long-running server (listens on port)

## Naming Conventions

**Files:**
- `.ts` (TypeScript) for backend and build scripts
- `.tsx` (React + TypeScript) for web components
- `.sol` (Solidity) for contracts
- Route handlers: lowercase + dash (e.g., `gateway.ts`, `auth.ts`)
- Components: PascalCase (e.g., `WalletButton.tsx`, `EndpointCard.tsx`)

**Directories:**
- Features / domains: lowercase + plural (e.g., `routes/`, `contracts/`)
- Grouped code: short descriptive name (e.g., `x402/`, `erc8004/`, `net/`)
- Pages: `pages/`; utilities: `lib/`; reusables: `components/`

**Functions & Variables:**
- camelCase throughout
- Auth context: `useAuth()`, `AuthProvider`
- Wallet context: `useWallet()`, `WalletProvider`
- API client: `api.endpoints()`, `api.stats()`, `api.calls()`
- Store methods: `store.listEndpoints()`, `store.addCall()`
- x402 helpers: `buildPaymentRequirements()`, `decodePaymentHeader()`

**Types:**
- PascalCase for types/interfaces
- Domain-specific: `GatedEndpoint`, `CallRecord`, `PaymentRequirements`
- Enums: PascalCase (e.g., `SettlementMode`)

## Where to Add New Code

**New Feature — Seller Dashboard Widget:**
- Component file: `web/src/components/[FeatureName].tsx`
- If state-heavy: add hook to `web/src/lib/` (follow useAuth/useWallet pattern)
- If it needs data: add method to `web/src/lib/api.ts`
- Import in: `web/src/pages/Dashboard.tsx` or a new page in `web/src/pages/`

**New API Endpoint:**
- Route handler: `src/routes/[domain].ts` (or add to existing if same domain)
- Data model: extend `src/types.ts` if needed
- Store method: add to `store.ts` export
- Example: payment endpoint → `src/routes/api.ts` (seller control plane)

**New Payment Scheme (beyond exact USDC):**
- Protocol logic: `src/x402/protocol.ts` (extend `buildPaymentRequirements`, handle new scheme)
- Signature: `src/x402/signer.ts` (new signing method)
- Verification: `src/x402/facilitator.ts` (add `verifyPayment` variant)
- Settlement: `src/x402/chain.ts` (new settlement handler)

**New x402 Feature (e.g., ERC-8004 checks):**
- Core logic: new file in `src/erc8004/` (or `src/net/`, `src/x402/`)
- Integration point: call from `src/routes/gateway.ts` before upstream proxy

**Utilities / Helpers:**
- Shared math: `src/revenue.ts` (or create `src/math.ts` if growth warrants)
- Network: `src/net/ssrf.ts` (URL validation, private IP checks)
- Web helpers: `web/src/lib/` (address formatting, constants, etc.)

**Tests:**
- Unit tests: not set up; would go co-located or in `__tests__/`
- E2E: agent demo at `src/agent/demo-agent.ts` (runnable CLI)

## Special Directories

**`data/`:**
- Purpose: Local file store location
- Generated: At runtime (creates `db.json` on first write)
- Committed: No (in .gitignore)
- Use: Dev/local server only; Vercel uses Redis instead

**`dist/`:**
- Purpose: Compiled server code (output of `tsc -p tsconfig.server.json`)
- Generated: By `npm run build:server` or `npm run vercel-build`
- Committed: No (in .gitignore)
- Use: Imported by api/index.ts and long-running server

**`web/dist/`:**
- Purpose: Built static files (output of Vite)
- Generated: By `npm run build`
- Committed: No (in .gitignore)
- Use: Served by Express in src/app.ts if present; Vercel CDN replaces this

**`contracts/out/`:**
- Purpose: Compiled contract ABIs and bytecode
- Generated: By `npm run contracts:build` (solc)
- Committed: Yes (needed for on-chain interactions)
- Use: Contract deployment scripts reference these

**`.vercel/`:**
- Purpose: Vercel deployment metadata
- Generated: By Vercel CLI
- Committed: Yes (contains project ID, not secrets)
- Use: Vercel platform integration

**`.planning/codebase/`:**
- Purpose: GSD codebase analysis documents
- Generated: By /gsd-map-codebase
- Committed: Yes (living documentation)
- Contents: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, etc.
